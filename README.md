# animename

Torznab-прокси между Prowlarr и Sonarr. Переписывает заголовки раздач RuTracker в вид,
который Sonarr умеет разбирать, не трогая ни Sonarr, ни Prowlarr.

```
Атака титанов / Shingeki no Kyojin [TV-1] [1-25 из 25] [RUS(int), JAP+Sub] [2013, приключения, BDRip] [1080p]
  -> Shingeki no Kyojin S01 [BDRip 1080p]

Фрирен, провожающая в последний путь / Sousou no Frieren [TV] [1-17 из 28] [2023, WEB-DL] [1080p]
  -> Sousou no Frieren S01E01-E17 [WEB-DL 1080p]

Твин Пикс / Twin Peaks / Сезон: 1 / Серии: 1-8 из 8 (Дэвид Линч) [1990, США, BDRip 1080p]
  -> Twin Peaks S01 [BDRip 1080p]
```

Без прокси Sonarr видит такие релизы как `Unknown Series` и молча их отбрасывает.

## Как это работает

```
Sonarr  --Torznab-->  animename  --Torznab-->  Prowlarr  -->  RuTracker
        <--  RSS с переписанными <title>  <--  RSS как есть
```

* **Запросы.** Sonarr добавляет к названию номер серии (`Shingeki no Kyojin 05`, `Title S01E05`,
  `Title (Season 2)`), иногда год (`Attack on Titan 2013 37`) и параметры `season`/`ep`.
  RuTracker по таким строкам ничего не находит, поэтому прокси отрезает хвост и не передаёт
  `season`/`ep` дальше. Фильтрацию по сериям Sonarr делает сам.
* **Дедупликация.** Sonarr перебирает все алиасы сериала и каждую серию отдельно:
  `Attack on Titan S2`, `Attack on Titan Season 2`, `Attack on Titan 01` ... `Attack on Titan 25`.
  После очистки это один и тот же запрос, и ответ берётся из кэша по ключу
  (индексер, `q`, `cat`, страница) без учёта типа запроса, так что поиск сезона и поиск
  серий тоже сворачиваются в один. TTL задаёт `CACHE_TTL`, по умолчанию 10 минут.
  Параллельные одинаковые запросы ждут первый, а не уходят в Prowlarr. RSS-запросы без `q`
  не кэшируются, чтобы не задерживать новинки. Заголовок ответа `X-Animename-Cache`
  показывает `HIT`, `MISS` или `SKIP`.
* **Фильтр языков.** Sonarr перебирает и алиасы с TVDB на других языках: `Ataque de los
  Titanes`, `L'Attaque des Titans`, `進撃の巨人`, `Атака титанів`. На RuTracker они бесполезны,
  поэтому дальше идут только запросы на русском и английском (ромадзи тоже латиница и
  считается английским), а на остальные прокси сразу отвечает пустым RSS, не трогая Prowlarr.
  Набор языков задаёт `QUERY_LANGUAGES`, `QUERY_SKIP` и `QUERY_ALLOW` дают ручные исключения.
* **Ответы.** В каждом `<item>` меняется только текст `<title>`. Всё остальное, включая `guid`
  и ссылки на скачивание, уходит в Sonarr байт в байт. Заголовки, которые не удалось
  распознать, остаются как были.
* **Скачивание.** Ссылки в ответах по-прежнему ведут в Prowlarr, Sonarr качает `.torrent`
  напрямую у него. Если Sonarr не видит Prowlarr по сети, задайте `PUBLIC_URL`, и ссылки
  будут переписаны на адрес прокси, который проксирует и `/download`.

Зависимостей нет: только стандартная библиотека Python 3.11+.

## Быстрый старт

1. Добавьте сервис в `docker-compose.yml` (см. `docker-compose.example.yml`):

   ```yaml
   services:
     animename:
       build: ./AnimeName
       environment:
         UPSTREAM_URL: http://prowlarr:9696
       restart: unless-stopped
   ```

2. Узнайте id индексера RuTracker в Prowlarr: откройте индексер, в поле Torznab URL будет
   `http://prowlarr:9696/<id>/`.

3. В Sonarr: Settings → Indexers → Add → **Torznab (Custom)**:

   | Поле | Значение |
   |---|---|
   | URL | `http://animename:8080/<id>` |
   | API Path | `/api` |
   | API Key | API-ключ **Prowlarr** |
   | Categories | `5070` (TV/Anime); при желании добавьте `5000` |
   | Anime Categories | `5070` |

4. Если Prowlarr сам синхронизирует RuTracker в Sonarr, отключите у этого индексера
   синхронизацию (Prowlarr → индексер → Sync Profile / теги), иначе релизы будут дублироваться.

### Настройки индексера RuTracker в Prowlarr

Prowlarr отдаёт заголовки не в том виде, в каком они на сайте. Для всех TV-категорий,
включая аниме, его парсер всегда переписывает `(ТВ-2)` в `(S2)`, `[12 из 12]` в `E12 of 12`,
а `Сезон: 1 / Серии: 1-8 из 8` в `S1E1-8 of 8`. Прокси понимает обе формы.

Опции самого индексера лучше выключить, прокси делает их работу аккуратнее:

* **Strip Russian letters** выкидывает кириллицу вместе с полезной информацией:
  `[1-25 из 25]` превращается в `[1-25 25]`, `[ТВ]` без номера исчезает совсем, а от шапки
  `Атака Титанов (ТВ-2)` остаётся голое `(S2)`. Прокси справляется и с этим, но запас
  прочности меньше.
* **Add RUS to titles** дописывает `RUS` ко всем заголовкам. Для переписанных заголовков
  прокси это не влияет, для остальных Sonarr решит, что релиз только на русском.
* **Move first/all tags to end** переставляет скобки. Тоже поддерживается, но смысла нет.

### Настройки индексера в Sonarr

У индексера, который указывает на прокси, включите **Anime Standard Format Search**.
Без этой опции Sonarr при поиске сезона аниме, у которого все серии уже вышли, не шлёт
ни одного запроса: сезонные запросы он строит только из сезонных алиасов сценовых
маппингов, а у большинства тайтлов их нет. С опцией уходит `tvsearch` с названием и
номером сезона, прокси убирает номер, и RuTracker ищет по названию.

## Настройки

Все настройки задаются переменными окружения.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `UPSTREAM_URL` | `http://prowlarr:9696` | Адрес Prowlarr |
| `LISTEN_HOST` / `LISTEN_PORT` | `0.0.0.0` / `8080` | Где слушать |
| `OVERRIDES_FILE` | | TOML с правилами для отдельных тайтлов (см. ниже) |
| `PACK_STYLE` | `season` | Как подписывать полную раздачу: `season` → `S01`, `range` → `S01E01-E25` |
| `MAX_EPISODES` | `100` | Раздачи с бо́льшим числом серий не переписываются |
| `RELEASE_GROUP` | | Суффикс релиз-группы, например `RuTracker` → `...-RuTracker` |
| `TITLE_PICK` | `first` | Какую латинскую часть брать за название: `first` (обычно ромадзи) или `last` (обычно английское) |
| `FORWARD_SEASON` | `false` | Передавать ли `season`/`ep` в Prowlarr. Для аниме на RuTracker это мешает |
| `PUBLIC_URL` | | Адрес прокси, на который переписывать ссылки скачивания |
| `CACHE_TTL` | `600` | Сколько секунд хранить ответы на поисковые запросы с `q`. `0` выключает кэш |
| `CACHE_SIZE` | `256` | Сколько ответов держать в кэше, старые вытесняются |
| `QUERY_LANGUAGES` | `ru,en` | Языки, на которых запросы уходят в Prowlarr. `any` выключает фильтр |
| `QUERY_SKIP` | | Регулярное выражение без учёта регистра. Запросы с таким `q` всегда получают пустой RSS |
| `QUERY_ALLOW` | | Регулярное выражение. Запросы с таким `q` всегда уходят в Prowlarr, минуя фильтр языков |
| `LOG_LEVEL` | `INFO` | `DEBUG` покажет каждый проксируемый запрос и нераспознанные заголовки |
| `UPSTREAM_TIMEOUT` | `60` | Таймаут запроса к Prowlarr, секунды |

### Overrides

Для тайтлов, у которых нумерация RuTracker не совпадает с TVDB или у Sonarr нет нужного
алиаса, есть файл правил (`config/overrides.example.toml`):

```toml
[[override]]
match = "^One Piece$"      # регулярное выражение по очищенному латинскому названию
skip = true                # не переписывать вовсе

[[override]]
match = "^Shingeki no Kyojin"
title = "Attack on Titan"  # подставить это название
season = 4                 # и этот номер сезона
```

### Как определяется язык запроса

Без внешних библиотек, по трём признакам:

* **Алфавит.** Кана, иероглифы, хангыль, греческий, арабский, иврит, тайский сразу считаются
  чужим языком. Кириллица с буквами `і ї є ґ ў ј љ њ ћ ђ џ` считается не русской.
* **Служебные слова на латинице.** `los`, `del`, `des`, `dei`, `und`, `der` и подобные
  выдают испанский, французский, итальянский, немецкий или португальский. Слова, которые
  встречаются в английских названиях или в ромадзи (`de`, `no`, `die`, `uma`, `non`...),
  намеренно не учитываются, а английские `the`, `of`, `in` перевешивают: `El Hazard:
  The Magnificent World` остаётся английским.
* **Запросы без букв** (`86`) пропускаются всегда.

Проверить решение для конкретного запроса можно командой `animename query` (см. ниже).
Если какой-то тайтл с французским или итальянским названием не проходит
(`Le Chevalier D'Eon`), добавьте его в `QUERY_ALLOW`. Заголовок `X-Animename-Skip`
в ответе прокси содержит причину отказа.

## Что именно делает парсер

* Название берётся из латинской части шапки `Русское / Latin [TV-1] ...`. Хвосты вроде
  `2nd Season`, `Season 2`, `II`, `Part 2` убираются, а номер сезона из них используется,
  если в скобке `[TV]` его нет. Год в скобках (`Hunter x Hunter (2011)`) сохраняется,
  режиссёр в скобках убирается.
* Сезон: `[TV-N]` → `N`; без номера → хвост названия → `1`.
* Серии: `[1-25 из 25]` и `[25 из 25]` → полная раздача; `[1-17 из 28]` → `E01-E17`;
  `[13-22 из 22]` → `E13-E22`; `[1-1122 из >1122]` → онгоинг без конца, при превышении
  `MAX_EPISODES` не переписывается.
* Качество: источник (`BDRip`, `BluRay Remux`, `WEB-DL`, `WEBRip`, `HDTV`, `DVDRip`),
  разрешение (`1080p`, `1920x1080` → `1080p`, при нескольких берётся максимальное),
  кодек (`x264`, `x265`, `AV1`) и `10bit`.
* Языковые теги (`[RUS(int), JAP+Sub]`) в новый заголовок не попадают. Sonarr v4 в этом
  случае подставляет язык оригинала сериала.
* `[Movie]`, `[OVA]`, `[ONA]`, `[Special]` не переписываются: Sonarr не сопоставит их с сериями.

## Если запросы всё равно доходят до Prowlarr

Как отличить запрос через прокси от прямого:

* **Колонка Source в истории Prowlarr.** Прокси подписывает свои запросы User-Agent'ом
  `animename/...`, и Prowlarr показывает источник `animename`. Если источник `Sonarr`,
  запрос пришёл напрямую, минуя прокси.
* **Хвост запроса.** Через прокси запрос никогда не заканчивается номером серии:
  `Ataque a los Titanes (2013) 31` в истории быть не может, он превратился бы в
  `Ataque a los Titanes (2013)` и был бы отсечён фильтром языков.
* **Счётчики.** `curl http://animename:8080/health` показывает `stats`: сколько запросов
  пришло, сколько ушло в Prowlarr, сколько отсечено, сколько взято из кэша. Нули при
  активном Sonarr означают, что Sonarr ходит не сюда.
* **Логи.** `docker compose logs animename` на уровне INFO пишет `forward:`, `skip:` и
  `cache:` для каждого поискового запроса, на DEBUG ещё и `query:` с очисткой.
* **CLI.** `animename query "<текст запроса>"` воспроизводит решение прокси.

Если запросы идут напрямую, у Sonarr остался индексер, который Prowlarr синхронизировал сам:

1. Prowlarr → Settings → Apps → Sonarr → Tags: задайте тег, например `sonarr`. С этого
   момента в Sonarr синхронизируются только индексеры с таким тегом. У RuTracker тега
   не должно быть, иначе Prowlarr заново создаст прямой индексер при следующей синхронизации.
2. Sonarr → Settings → Indexers: удалите прямой индексер RuTracker. Должен остаться один,
   с URL `http://animename:8080/<id>`.

## Ограничения

* Номер `[TV-N]` на RuTracker не всегда равен номеру сезона на TVDB (разбиение на части,
  перезапуски, длинные онгоинги вроде One Piece или Naruto). Для таких сериалов нужны
  overrides, иначе Sonarr может взять не ту раздачу. `MAX_EPISODES` ограничивает ущерб.
* Если файлы внутри торрента названы по-русски, Sonarr может не разобрать их при импорте.
  Это за пределами прокси.

## CLI

Проверить, во что превратится заголовок, можно без запуска сервера:

```bash
animename convert "Атака титанов / Shingeki no Kyojin [TV-1] [1-25 из 25] [2013, BDRip] [1080p]"
```

```bash
animename convert --json --overrides config/overrides.toml < titles.txt
```

Посмотреть, что прокси сделает с запросом Sonarr: как очистит, какой язык определит и
уйдёт ли запрос в Prowlarr:

```bash
animename query "Shingeki no Kyojin (Season 2) 05" "Ataque de los Titanes 05" "Атака титанов"
```

```
'Shingeki no Kyojin (Season 2) 05' -> 'Shingeki no Kyojin' [en] forward
'Ataque de los Titanes 05' -> 'Ataque de los Titanes' [es] skip: language=es not in en,ru
'Атака титанов' -> 'Атака титанов' [ru] forward
```

Запуск сервера без Docker:

```bash
UPSTREAM_URL=http://localhost:9696 animename serve --port 8080 --languages ru,en
```
